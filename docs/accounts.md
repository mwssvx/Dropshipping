# Accounts and keys you create

Nothing here was signed up for on your behalf. Until these exist, the app runs on local stand-ins.

| service | needed for | stand-in today | what to set |
| --- | --- | --- | --- |
| Supabase | production database and login | PGlite (local Postgres) + built-in email/password | `DATABASE_URL`; Supabase Auth replaces the dev auth module in M4 |
| Stripe | real payments, Connect payouts, Tax, plan billing | `FakePaymentProvider` with signed webhooks; payouts, holds and plan changes are simulated | `PAYMENTS_PROVIDER=stripe`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`. Turn on Connect (Express accounts) in the Stripe dashboard. Create three monthly prices ($19, $49, $149) and set `STRIPE_PRICE_STARTER`, `STRIPE_PRICE_GROWTH`, `STRIPE_PRICE_SCALE`. Point a webhook at `/api/webhooks/payments` with `payment_intent.succeeded`, `payment_intent.payment_failed`, `customer.subscription.*`, and (as a Connect webhook) `account.updated` and `payout.*`. For exact tax rates, turn on Stripe Tax for connected accounts and set `STRIPE_TAX=on` |
| CJ Dropshipping | supplier import and fulfilment | demo supplier (`DEMO_SUPPLIER=on`); `CjSupplier` is written but not yet run against a live account | `CJ_API_KEY` (from CJ: My CJ > Authorization > API). Turn on wallet auto-pay in CJ so placed orders get paid |
| AliExpress Open Platform (optional second supplier) | importing from AliExpress links and placing orders there | off; `AliExpressSupplier` is written but not yet run against a live account | register an app at openservice.aliexpress.com with the Dropshipping API permission, set `ALIEXPRESS_APP_KEY` and `ALIEXPRESS_APP_SECRET`, authorise the AliExpress buyer account the orders come from and set its access token as `ALIEXPRESS_ACCESS_TOKEN` (it expires; renew it before then). Save a card in that account so orders get paid |
| Vercel | hosting previews and production; the fulfilment job in `apps/web/vercel.json` (daily on the free plan; set it to every 30 minutes on a paid plan) | none (runs locally) | connect the repo, set `CRON_SECRET`. For a `*.vercel.app` test copy also set `NEXT_PUBLIC_STORE_SUBDOMAINS=off`. For merchants' own domains: an access token (Account Settings > Tokens) as `VERCEL_API_TOKEN`, plus `VERCEL_PROJECT_ID` and `VERCEL_TEAM_ID` |
| Expo (EAS) | building the iOS and Android app, push notifications | Expo Go; the app's web build in tests | run `eas init` in `apps/mobile` (adds the project id push needs), then `eas build --profile preview`. Set `EXPO_PUBLIC_API_URL` per profile in `apps/mobile/eas.json`. If you turn on push security, set `EXPO_ACCESS_TOKEN` on the web app |
| Apple Developer ($99/yr), Google Play ($25 once) | TestFlight, Play internal testing, store listings | none | create the app in App Store Connect and put its id in `eas.json` (`ascAppId`); for Google, a service account key saved as `apps/mobile/google-play-service-account.json` (never committed). Then `eas submit` |
| Resend | order emails (confirmation, shipped, delivered) | logged to the console and the `emails` table | `RESEND_API_KEY`, `EMAIL_FROM` on a verified domain |
| Anthropic API | AI agents (M5) | rule-based demo brain with the same tools and approval rules | `ANTHROPIC_API_KEY` (console.anthropic.com > API keys). Set a monthly spend limit there too; each store also has its own AI budget in the app |
| Google Cloud (OAuth client) | the Assistant reading the owner's Gmail, sending email as them, and reading/adding Google Calendar events (Connectors page) | `FakeGoogleProvider`: a pretend inbox and calendar; "Connect Google" goes straight back as if the owner said yes | create a project at console.cloud.google.com, enable the Gmail API and Google Calendar API, set up the OAuth consent screen (scopes `gmail.readonly`, `gmail.send`, `calendar.events`, `openid`, `email`; sensitive scopes need Google's verification before strangers can connect, test users work before that), create an OAuth client (web application) with redirect URI `https://<domain>/api/connectors/google/callback`, and set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. Also set `CONNECTOR_SECRET` (any long random string) so saved sign-ins are encrypted at rest |
| A domain | the platform's address; stores get `<handle>.<domain>` | `localhost` | set `NEXT_PUBLIC_ROOT_DOMAIN`, and add the domain plus a wildcard `*.<domain>` to the Vercel project |

Also set `STAFF_EMAILS` to the email addresses (comma-separated) of the people who may open `/staff` to warn or pause stores and answer appeals.
